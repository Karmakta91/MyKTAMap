📚 Plans serveur
🛠️ Système & maintenance
🛠️ Debug

Toggle active la console verbeuse (tracker, fetch, etc.). Le bouton 📋 affiche les logs capturés directement (utile aussi sans plan chargé).

📊 Inspecteur

Topo lisible de ce qui est actuellement chargé en mémoire côté navigateur : localStorage, IndexedDB, Cache PWA, état runtime. Utile pour comprendre la consommation et diagnostiquer un problème.

🔄 Mise à jour

Force une mise à jour douce : purge le cache des assets (HTML/JS/CSS) et re-télécharge la dernière version depuis le serveur. Tes données sont préservées (plans mémorisés, sessions, préférences, code d'accès). Nécessite une connexion Internet active.

🆘 Désinscrire le Service Worker

À essayer si la mise à jour douce ci-dessus n'a pas suffi (badge footer toujours sur « ancienne → nouvelle » après reload). Désinscrit le SW et purge les caches PWA — au prochain chargement, un SW tout neuf prend le relais. Tes données restent intactes (plans, sessions, préférences, code d'accès). Moins destructif que le Reset complet ci-dessous.

💥 Réinitialisation

Vide TOUT le stockage de l'app (cache, plans mémorisés, sessions, préférences). Cette action est irréversible et nécessite une connexion Internet pour re-télécharger les assets.

📖 Que fait l'app sur le réseau ?
MyKTAMap est une PWA 100% client-side. Tout ce que tu crées (annotations, sessions, plans mémorisés, calibrations KMZ, préférences) reste dans ton navigateur. Le serveur Nginx ne fait que servir des fichiers statiques. Aucun backend applicatif, aucune base de données serveur, aucun analytics, aucun cookie de tracking.

🔍 Comment vérifier toi-même
  1. Journal interne : bouton « 📋 Voir le journal réseau » dans la même section — logue en temps réel toutes les requêtes émises par l'app.
  2. DevTools navigateur (F12) : onglet « Network » / « Réseau » → tu vois toutes les requêtes, indépendamment de ce que l'app raconte. Filtre par méthode pour vérifier qu'il n'y a aucun POST/PUT/PATCH/DELETE.
  3. Mode hors-ligne strict : coche le toggle dans la même section. Le navigateur refusera activement toute requête non-whitelistée — l'app reste 100% fonctionnelle.
  4. Content Security Policy : F12 → Network → première requête (HTML) → onglet Headers → cherche Content-Security-Policy. Le serveur Nginx demande au navigateur de bloquer toute connexion non whitelistée (connect-src 'self' https://www.gstatic.com).
